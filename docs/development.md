# Development

Commands are run from the `server/` directory unless noted otherwise.

## Build and check

- `gleam check` — typecheck only (fast; use while editing).
- `gleam build` — full build of the project (use before committing or when you need compiled artifacts).

## Regenerate SQL queries

`src/server/sql.gleam` is generated by [squirrel](https://github.com/giacomocavalieri/squirrel) from the `.sql` files in `src/server/sql/`. Do not edit `sql.gleam` by hand.

- Add or change a query: edit/add a `.sql` file under `src/server/sql/`, then from `server/`:

  ```sh
  gleam run -m squirrel
  ```

- Remove a query: delete its `.sql` file and re-run the same command.

## Rebuild frontend static assets

The browser bundle under `server/priv/static/` is generated from the `client/` package (Lustre). Those files are gitignored; regenerate them after client changes:

```sh
# from client/
gleam run -m lustre/dev build --outdir=../server/priv/static --no-html=true
```

## Database migrations

Migrations live in `server/migrations/` and are applied at server startup (see `src/server/migrate.gleam`).

## Printer API (JSON)

Thin Wisp routes over `printer_manager` (the single public API). All responses are JSON.

| Method | Path | Body | Notes |
| ------ | ---- | ---- | ----- |
| `GET` | `/api/printers` | — | List `{ id, status }` for every printer |
| `GET` | `/api/printers/:id` | — | One printer; 404 if unknown |
| `POST` | `/api/printers/:id` | `{"action":"start"\|"pause"\|"resume"\|"cancel", "file_id"?: Int}` | Accepted (202); result arrives asynchronously |
| `GET` | `/api/printers/:id/events` | — | First-cut SSE: waits for one status event, returns `text/event-stream` with a single `status` frame, then unsubscribes |
| `GET` | `/api/printers/ws` | — | WebSocket transport for the dashboard server component (see below) |

Status shape (from `status_encoder` in `server/src/server/web_server.gleam`):

```json
{
  "connection": { "state": "connected" | "connecting" | "disconnected", "reason"?: "..." },
  "print": "idle" | "printing" | "paused" | "needs_attention" | "complete" | "cancelled" | "errored",
  "progress": { "percent": 0.0, "time_remaining_seconds": Int | null } | null,
  "temperatures": [{ "name": "nozzle" | "bed", "current": 0.0, "target": 0.0 }],
  "trays": [{ "index": Int, "slots": [{ "index": Int, "material": String | null, "color": String | null, "remaining_percent": Float | null }] }],
  "faults": [{ "code": String, "message": String, "severity": "warning" | "error" }]
}
```

True long-lived SSE (multi-event stream via mist) is an intentional follow-up; the current endpoint is a single-event first cut.

## Live dashboard (Lustre server component)

The dashboard's printer grid is a [Lustre server component](https://lustre.hexdocs.pm/lustre/server_component.html) rendered live on the server:

- `src/server/dashboard_component.gleam` — the component app: model is the latest `PrinterStatus` per printer; the view reuses `client/dashboard.printer_box` for shared card markup.
- `GET /api/printers/ws` — WebSocket transport, intercepted at the mist layer (before the Wisp middleware stack). One component runtime per connection: it subscribes to `printer_manager` for status fan-out, takes a `ListPrinters` snapshot on connect, and is shut down on disconnect (the subscription is dropped too).
- `GET /vendor/lustre-runtime.mjs` — the pre-built `<lustre-server-component>` client runtime, served from Lustre's `priv/static`. Every page loads it via a `<script type="module">` tag so client-side navigation to the dashboard works.
- `client/dashboard.gleam` embeds the element: `server_component.element([server_component.route("/api/printers/ws")], [])`.
